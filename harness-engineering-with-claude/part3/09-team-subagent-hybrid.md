# 팀 / 서브에이전트 / 하이브리드

팬아웃을 구현하는 방법은 두 가지임.
팀을 만들어 돌리거나 서브에이전트를 병렬 호출하거나.

같은 패턴이라도 어떤 방식을 쓰느냐에 따라 결과 품질과 비용이 달라짐.

## 학습 목표

에이전트 팀과 서브에이전트의 통신 방식 차이를 이해하고, 6개 기준으로 상황에 맞게 실행 모드 고르는 것을 배운다.

## 핵심 키워드

- 에이전트 팀
- 서브에이전트
- 하이브리드
- TeamCreate
- 통신 토폴로지
- 세션 제약

## 줄거리 및 요약

### 팀을 짤까, 그냥 각자 시킬까

8장에서 배운 6가지 아키텍처 패턴 중 팬아웃을 택했다고 가정하자. 그랬을 때,

"팬아웃을 TeamCreate로 에이전트 팀을 만들어 돌릴까? 아니면 에이전트 도구로 서브에이전트를 병렬 호출해서 돌릴까?"

이 선택에 따라 결과 품질, 토큰 비용, 디버깅 난이도가 전부 달라짐.
팀 모드는 상호 검증과 발견 공유로 품질을 끌어올리지만 오버헤드가 높음
서브에이전트 모드는 가볍고 빠르지만 에이전트 사이의 상충 감지 못해.

### 실행 모드별 트레이드오프

[메타스킬 SKILL.md의 Phase 2-1](.claude/skills/harness/SKILL.md)을 보면 실행 모드를 세 가지로 구분하고, 기본값을 팀으로 정해두었음.

- 에이전트 팀(기본)
- 서브에이전트(대안)
- 하이브리드

어떤 모드를 선택해야 할지 결정하기 어렵다면 아래 여섯 가지 요소를 기준으로 판단하면 선택 근거가 한결 선명해짐.

- 팀원 수
- 팀원 간 소통
- 교차 검증
- 오버헤드
- 활성 제약
- 디버깅 난이도

또한 모드에 따라서 적절한 데이터 전달 프로토콜 역시 달라져.

### 실행 모드 결정

[메타스킬 SKILL.md의 Phase 2-1](.claude/skills/harness/SKILL.md)은 다음 3단계를 순서대로 적용하도록 명시함

1. 먼저 에이전트 팀으로 설계 가능한지 검토 - 2인 이상이면 기본값(팀)
2. 팀 내 통신이 구조적으로 불필요하고, 팀 오버헤드가 이득보다 클 때만 서브에이전트 선택
3. Phase별 특성이 확연히 다르면 하이브리드 고려 - 각 Phase의 실행 모드를 오케스트레이터에 명시.
